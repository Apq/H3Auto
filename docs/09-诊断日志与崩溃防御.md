### 16.2 日志分级（ConfigLog.inc.cpp）

- 五级：trace < debug < info < warn < error；入口 `LogTrace/LogDebug/LogInfo/LogWarn/LogError`，行格式 `[时间] [级别] 消息`。
- 定级标准（0.5 对外版修订）：玩家可感知的关键事件（配置加载与生效值/控制权切换/状态迁移/存读档/施法成功/自动停止）=info；执行轨迹与分支细节=debug；异常业务信号（配置回退/动作失败交回玩家/状态机 illegal 迁移/跟踪 mismatch 聚合汇总/资源加载不符）=warn；一切 SEH 异常点与初始化失败=error。SEH `__except` 内一律 error（含异常码），不降级。
- **崩溃防御日志（[§18](<#section-18>)）**：`[Guard]` 前缀——启动 `崩溃自记录已启用`=info；钩子异常捕获/熔断/致命报告/版本门卫拒绝=error（含异常码、出错地址、模块+偏移）。玩家报崩溃时先找 `[Guard] ====== 未处理异常` 报告段；日志戛然而止且无报告不能单独判定强杀或插件责任（[§18.3](<#section-18-3>) 边界），转要 Windows 事件查看器 1000 条目。
- **版本自证**：启动第一行 `打铁助手 v0.5.2026.1005 | DLL=<实际加载路径>`（`LogSelfVersion_`，Entry.inc.cpp；读自身 VERSIONINFO 与 .rc 同源）。排查「更新了没生效」类问题（多包双装/旧包残留）先看这行。
- **mismatch 聚合**：跟踪失效场景不再逐条刷 warn（玩家日志 2026-10-02 实证 4 小时 558 条淹没真信号）——同一场（attempt）只报首条详情，其余静默计数，`ResetAutoState` 收账一条汇总；正常玩法 0 条。
- `[Logging] MinLevel`（缺省 info）控制落盘下限；帮助界面下拉可运行时切换并写回 `H3Auto.user.ini`，立即生效。
- **debug 级诊断覆盖**（玩家报 BUG 时 `MinLevel=debug` 复现后打包发回即可定位）：目标选择候选明细与选中结果（`[Target]`）、保活候选与施法参数（`[Protect]`）、自动停止取样与外推（`[AutoStop]`）、接管判定快照（`[Takeover]`）、动作分发快照（`[Auto] dispatch`）、施法请求/投键/等待（`[Spell] request/posted/wait`）、面板打开各阶段与存读档入口（`[Panel]`）、战场拾取点击与近战标示（`[Panel] pick/marker`）。默认 info 级不落盘这些细节。

### 16.3 帮助界面扩展与日志打包

- 帮助模态 480×336 → 480×440（`GetHelpModalRect_`；日志级别行 + 打包按钮行 + 召唤说明行三次加高，412 为中间值）：新增「日志级别:」下拉（全部/调试/信息/警告/错误，对应 trace..error）与「打包日志」按钮；展开列表盖在按钮上层，点外部收起。开源地址行（`help.link`）点击复制 URL 到剪贴板，成功闪绿 1.2s（`help.link_flash` / `s_help_link_flash_tick`），失败提示剪贴板被占用。
- 打包（modules/LogPack.inc.cpp）：DLL 同目录最近 5 个本插件日志按时间降序（2026-10-07 起收集模式与日志器同源：`g_log_base` = DLL 文件名去扩展名，即 `<基名>_*.log`；与其他插件同目录也只匹配自己的日志，DLL 被整合包改名后依旧正确，基名缺失才退回 `H3Auto_*.log`）、**完整文件**（2026-09-26 定稿：定位 BUG 需要开场初始化段，不再截尾部 2MB；历史上全量读曾致 32 位进程 UI 假死，超大 debug 日志打包耗时自担）后 **LZMA 压缩为 .7z**（LZMA SDK 源码级集成，lzma/ 目录；.7z 容器手写，明文 header，每文件独立 folder，另附 00_说明.txt——UTF-8 带 BOM，内容为 help.pack_note：发送目的地与 QQ 号，解压即可复制；游戏内任何自绘/系统对话框文字都无法复制，QQ 号只能放进包内文件），输出 `H3Auto_logs_YYYYMMDD_HHMMSS.7z` 于 DLL 同目录，复制到剪贴板只放 CF_HDROP 文件式（同资源管理器复制文件，QQ 聊天框 Ctrl+V 直接发送 .7z 文件；DROPFILES 头 20 字节布局自写，shellapi.h 在此工具链不可靠），**不附 CF_TEXT**：同一次剪贴板里再放文本格式，QQ 会优先粘贴成路径文字而不是文件。OpenClipboard 失败重试 5 次；成功提示含发送目标：QQ群 1042362808 / 740338251，或 QQ 712999712 私发。
- 成功提示 `help.pack_ok`（含 QQ 群粘贴与 712999712 私发指引），失败 `help.pack_fail`。

## 18. 崩溃防御与自记录（CrashGuard，2026-10-06）

背景：玩家反馈"游戏崩溃"（2026-10-06 三份日志），日志只能证明两次异常终止（末尾无 `DLL_PROCESS_DETACH` 的收尾重置行），崩溃本身零痕迹——硬崩溃杀进程时"代码跑过才写"的日志不会留痕。纯逻辑在 [CrashGuardCore.hpp](<../modules/CrashGuardCore.hpp>)（PolicyCoreTests 覆盖），钩子本体在 [CrashGuard.inc.cpp](<../modules/CrashGuard.inc.cpp>)（依赖 ConfigLog 落盘函数，[H3Auto.cpp](<../H3Auto.cpp>) 中紧随其后包含）。

<a id="section-18-1"></a>
### 18.1 分层防御（L1–L4）

- **L1 崩溃自记录**：`AddVectoredExceptionHandler(1)` 把过滤后的首次机会严重异常推入 8 条环形缓冲（`GetTickCount`/线程/异常码/出错地址/AV 操作与目标），`SetUnhandledExceptionFilter` 在进程终止前落盘全量报告：异常码（中文名）、AV 读/写/DEP 细节、出错地址、**所在模块+偏移**、首次机会历史、调用栈回溯（`CaptureStackBackTrace`，尽力而为）。链回前一个过滤器（可能是 HD Mod 的），无前驱返回 `EXCEPTION_CONTINUE_SEARCH` 交回 WER——崩溃表现与不装完全一致。日志前缀 `[Guard]`，报告与异常均为 error 级。
- **L2 钩子铠甲**：[§12](<01-总体架构与Hook.md#section-12>) 全部入口（`Hook_BltComplete`/`Hook_BattleMsgProc`/`HH_ShouldAutoExecute`/`HH_OnBattleActionExecute`/键盘回调）的 `__except` 过滤器统一为 `GuardCrashFilter_`：落盘异常码+地址+模块，返回 `EXCEPTION_EXECUTE_HANDLER` 吞掉，走安全默认（LoHook=`EXEC_DEFAULT` 放行；HiHook=按原参调 `GetDefaultFunc`；键盘=`CallNextHookEx` 透传）。**原版函数调用在 `__try` 之外**：游戏自身崩溃正常传播，不属于插件吞没范围（责任边界）。
- **L3 自熔断**：同一钩子累计异常达 8 次（`kFuseLimit`）→ 本进程内停用该路径（`GuardHookBlown_`，外壳先查标志直接走安全默认），防崩溃循环与 error 刷屏。
- **L4 版本门卫**：挂钩前 `GuardVerifySodBytes_` 校验 SoD 数据指纹（力场表 `0x63CF18`/`0x63CF2C`：numSquares 2/3、相对格 {0,-16}/{0,-16,-34}、DEF 名 "C15sp" 前缀，字节级取证见 `H3Note\BattleCrashFix逆向笔记.md`）。不吻合（完整版/HotA/改版 exe）→ 只保留日志、**不挂任何钩子**。崩溃自记录（L1）无条件安装。

<a id="section-18-2"></a>
### 18.2 崩溃上下文安全约束

UEF/VEH/过滤器内只用静态/栈缓冲 + 内核文件 API（`CreateFileW`/`WriteFile`/`CloseHandle`），不碰堆、不拿内核锁；环形缓冲用自旋锁（`InterlockedCompareExchange`，4096 次放弃）防多线程撕裂；全程 `__try/__except` 自包裹 + 重入标志；栈溢出（0xC00000FD）跳过栈回溯只写短行。日志路径逐行即开即写（`AppendUtf8LogLine`），已写行不因后续崩溃丢失。

<a id="section-18-3"></a>
### 18.3 方案边界（如实告知，捕获不到的）

- `TerminateProcess` 强杀（看门狗/任务管理器）：无任何回调。
- `__fastfail`（0xC0000409 栈保护）：系统故意绕过全部过滤器。
- 栈溢出到过滤器自身无栈可用：尽力而为。
- 逻辑性损坏（写错偏移落在合法内存，当场不崩、之后游戏代码崩）：运行时无法捕获，靠 L4 门卫 + 写前验证 + 测试压制；发生后靠 L1 报告的模块+偏移归因（落在 `H3Auto.dll` 还是 `Heroes3.exe` 一眼可辨）。

<a id="section-18-4"></a>
### 18.4 日志判读口径

- 正常退出：日志末尾有孤立 `Auto state reset` 行（`DLL_PROCESS_DETACH` 收尾）。
- 异常终止：无收尾行；若为未处理异常，末尾出现 `[Guard] ====== 未处理异常` 多行报告（含模块+偏移）。
- 启动行 `[Guard] 崩溃自记录已启用` 缺失 = 本机制未生效（旧版 DLL 或安装失败）。
- 版本门卫拒绝：`[Guard] SoD 数据指纹不匹配` + `已停用全部钩子`，进程继续跑原版游戏，仅记录。

## 判读限制

启动版本字符串是历史示例，实际加载版本以玩家日志为准。无 DETACH 收尾也可能来自强杀、过滤器失效或其它终止方式，不自动等同于本插件崩溃。本次只迁移已有证据，没有继续分析上一项玩家日志。
