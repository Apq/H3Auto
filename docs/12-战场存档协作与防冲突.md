# H3Auto 与战场存档协作与防冲突

2026-10-11 用户要求：玩家可以只启用任意一个插件，防冲突只在两者同时启用时生效；战场自动保存失败不重试。

## 启用与接口

只启用 H3Auto 时，找不到接口就保持原自动逻辑。只启用 H3BattleStore 时，其帧循环独立保存。两者都启用本次更新版本时，H3Auto 动态查询 patcher 注册表，在自动效果前协作。两个 DLL 无导入依赖、不强制加载对方，接口不存在不永久缓存，加载顺序不影响。两个DLL为游戏进程内常驻，不支持运行中FreeLibrary或热卸载。

| 键（由 H3BattleStore 发布，H3Auto 只读） | 类型与含义 |
|---|---|
| `H3BattleStore.BusyQuery.v1` | DWORD 函数地址，`BOOL (__stdcall*)()`；TRUE=保存/读档排队/确认/恢复/fatal，不得提交自动效果。 |
| `H3BattleStore.BeforeAutoAction.v1` | DWORD 函数地址，`BOOL (__stdcall*)(void* mgr)`；同步尝试本回合首档，FALSE=先让原版建立稳定玩家窗口，TRUE=可以继续。 |
| `H3BattleStore.RestoreEpoch.v1` | DWORD 成功恢复计数；取消或失败回滚不增加。 |

只查询 `VarFind/GetValue`、`VarGetValue`，不由 H3Auto `VarInit` 覆写对方值。命名带v1，签名变化须另版本名。H3BattleStore SoD 门卫通过才发布；旧H3Auto不调用接口，需要两个新版构建才能协作。

## 自动效果的顺序

生产共用 `BattleStoreAutomationAllowed_` 顺序为：Busy检查 → 处理恢复计数 → BeforeAutoAction → 再检查Busy；管理器身份仍一致才继续。两个接入点均位于任何自动效果之前：

- `HH_ShouldAutoExecute` 的orig==0分支；忙时返回0，让原版继续建立玩家待令窗口。原版函数在SEH保护体外恰好调用一次；orig!=0不改变。
- `TryAutoExecuteActiveStack`，覆盖BltComplete帧入口和BattleMsgProc消息入口；忙时返回false。随后才进入ForceField、保活、攻击魔法和部队命令。

战场首档尚未尝试时遵守 H3BattleStore 严格窗口。接管判定可能早于原版刷新active_stack，Before暂返FALSE，让原版刷新，后续帧/消息完成首档。已经尝试后，不再要求active_stack对齐以阻挡本回合后续动作。原版自动战斗、战术或尚未初始化不等待首档。

保存开始前消费回合尝试，失败（含SEH异常）本回合不重试，下一回合再尝试。失败不锁自动执行。保存过程如果重入帧/消息，Busy阻止施法/部队命令。

## 读档后

成功恢复计数变化时 `ResetAutoState()` + `BindStackTrackingFromBattle_()`，先置恢复处理闸并切手动，再清恢复前的命令管线、施法等待、免疫跳过和运行游标，保留已确认方案/规则。关闭面板触发刷新时，重入入口被处理闸挡住，SEH finally释放闸。玩家按F9再继续。取消确认或失败回滚不清运行态。

移动和近战游标从头开始：当前原生战场快照不含H3Auto运行进度，因此不能声称自动轨迹精确恢复。两插件使用各自存档目录，互不扫描删除对方文件。
