## 力盾战法（2026-10-06）

保持状态页第一行「力盾落点」；每套方案包含 `forcefield:{anchor_hex:[a,b]}`，
默认 `[-1,-1]`。不设独立 Tab 或启用开关，有落点即保持力盾，删光即不补盾。
沿用循环移动的坐标槽：点＋新增、点已有槽重选、右键删除，最多两个，A01 样式。
不捕获玩家首盾。草稿取消不修改生效方案；复用 BattleUI 屏障点选单格，不透传
部队动作，右键/ESC 恢复面板，不绘制蓝底。同场重打保留锚点但清除运行态。

在玩家控制权路径及自动部队动作投递之前扫描目标盾。活障碍必须 `def!=nullptr`，
模板为 `0x63CF18/0x63CF2C`，锚点/归属方匹配；不再检查完整覆盖格或障碍索引。
过期记录的 `def==nullptr`，不能用仍留在向量的模板/锚点误认现存盾。
纯策略按槽序选第一个配置且非 PRESENT 的目标；读取未知也尝试补施。

目标盾存在继续原施法通道，不在则最高优先补施。严格顺序：力盾 > 保活 > 其它状态 > 召唤。
原版固定持续 2，回合更新递减归零清除；只按场上存在判定，不缓存补施回合，
其它状态的剩余回合阈值不影响力盾。原版一回合一次英雄法术，两点同缺只补一个，
已经施法则继续部队动作，第二点留下一回合。无落点/无英雄不阻断原通道。

按用户测试要求取消魔法书、HasSpell、费用/魔力、禁魔宝物/地形及落点合法性预检，
直接 GetSpellExpertise/heroSpellPower + CastSideGuard + CastSpell，不做施后生成核验。
VOID 返回后补写本回合施法标记，避免同回合重复尝试；失败或阻止框返回仍继续动作，
不承诺本测试版一定有盾保护。第一点持续未生成会优先重试，第二点可能延后。
保留动画重入锁、有效行动窗口、代次/配置/控制模式检查和 SEH；生命周期变化不投递
旧动作，施法异常在有效战斗内切回 MANUAL。原版选法界面的限制与直接调用差异仍
记录于机制笔记，取消插件预检不等于证实原版直接调用在所有场景都安全。

战斗 JSON 为 v4，根版本/指纹及每套 forcefield 的两整数数组严格验证，不兼容旧格式。
H3AP9 为未使用的独立文本接口，不承载战法字段；生产持久化只走战斗 JSON。
力盾不关闭或改写用户的自动停止设置，仍默认预计剩余回合 4、敌方魔力阈值 6。

适用前提：敌方双格地面近战、角落三格布阵、每回合我方先行动；不自动布阵或保证
飞行/传送/远程/速度变化安全。静态证据与待验证项见
[机制考证](../../H3Note/力盾战法-机制考证.md)。游戏动作时序、双落点点选及无预检直接施法必须另做实测。

<a id="section-3"></a>
## 3. 英雄施法与自动停止规则

<a id="section-3-1"></a>
### 3.1 部队行动前英雄自动施法（快捷施法 / 循环施法）

- 每支部队行动前，英雄可先自动施放一个快捷法术。
- 由于每回合想施放的法术可能不同，支持**循环施法**：按回合轮换施放快捷施法的槽位。
- 循环施法只通过**快捷施法**功能实现（快捷键 1-9/0）。UI 单行最多 **10 个**快捷键槽位（`spellSlots[10]`），运行游标保存在本场部队跟踪表；原版快捷施法仍有 10 个键可选。

<a id="section-3-1-1"></a>
### 3.1.1 保活（聚灵/复活自动施救）

和循环施法不是一回事：循环施法绑在**某支部队行动前**；本条绑在**每次把控制权交给玩家时**（含本插件接管）。目的：**防止部队死光**。

- **保活方式（部队级，三选一，随方案与槽位规则一起存储、重排、提交；默认不保活）**：卡片底部「保活:」下拉框选：
  - **不保活**（默认，`PM_NONE`）：该队永不参与保活施法；
  - **剩余数量 ≤**：该队**剩余数量 ≤ 该队阈值**才施救（「剩≤」数字框仅此方式显示，默认 2，范围 0..2147483647；0 = 只救已全灭，仍要求有尸体格）；
  - **损失量大于恢复量**：已损血量（`死亡数 × 单兵满血 + 顶层已损 HP`，全灭即满损失）**严格大于**一次可恢复量才救。死亡数从英雄头像 Alt+右键显示的**战前军队数量**（`H3Hero::army`，与读档关联同一份）算起；不用战场上会被 F9 重置的 `count_at_start`，也不用按确定时的数量。可恢复量 = 法术表 `baseValue[等级] + 力量 × spEffect`，再加英雄法术特长（`0x4E6260`，无特长为 0）。复活与聚灵同一算法，各自读自己的法术表项。读不到表时退回基础 50×力量、高级 75×力量、专家 100×力量。无损失（已损 = 0）的部队永不触发。
- **施法通道（力盾 → 保活 → 保持状态 → 召唤，同一条）**：玩家方没有英雄时整条通道不走。有英雄时，每次行动（还有施法次数时）先补配置落点的缺失力盾，再判保活（本节，各队按自己的方式，选了「不保活」的队不参与）；没人该救再判「保持状态」（[§3.1.3](<#section-3-1-3>)）；仍不施法且召唤已启用（方案级 `g_summon[p].enabled`，召唤页勾选框，[§3.7](<#section-3-7>)/[§8.8](<06-设置面板与输入绘制.md#section-8-8>)）才转判召唤阈值。三个通道的 `CastSpell` 调用统一有 `g_cast_in_flight` 嵌套重入门卫与 `CastSideGuardEnter_/Leave_` 施法方校正（见下）。一回合英雄只施一次法。
- **判定时机**：事件型，**每次行动（控制权交给玩家）都判**。游戏一回合只允许施法一次：已施法/法力不足时静默跳过，之后的行动继续判。
- 参与范围：己方全部部队槽（跟踪表绑定 + 人类侧身份校验 + 开场数量 > 0），**战争机器不参与**（箭塔/弩车/急救帐篷/投石车/弹药车）；召唤物克隆槽不参与复活。
- 够格者中救谁：统一取**当前剩余总血量最低**的一支（全灭者剩余 0 天然最前）。
- 法术由插件自动选，与快捷施法完全无关，不占快捷施法槽：目标部队是亡灵（`undead` 标志位）→ 聚灵（`eSpell::ANIMATE_DEAD = 39`）；活体 → 复活（`eSpell::RESURRECTION = 38`）。对应法术没学（`learnedSpells` / `GetSpellExpertise = 0`）则该部队本回合保不了。
- 施法前提：法力足够（复活/聚灵固定耗魔 10）、本回合英雄未施过法。执行：插件直接调 `H3CombatManager::CastSpell(spell_id, 目标hex, cast_type, -1, 法术等级, 力量)`（SoD `0x5A0140`），目标格取该部队所在格。施法动画由游戏内部完成。一回合一次统一用游戏自己的 `heroCasted[side]`（`0x54B4`）：施法核心内部无条件写 `heroCasted[currentActiveSide]=1`，但插件在 0x4744D0 钩子里施法时该索引可能因行动循环时滞置错边，玩家方仍是 0 → 同一回合每次部队行动交还控制权（含士气额外行动）都判「未施过」连发。故施法成功后由 `MarkHeroCastThisTurn_` 把玩家方 `heroCasted[side]` 补写为 1；读取端即 `GetHeroCasted_`（玩家手动施法游戏自己置位，天然同口径）；每回合清零由游戏回合推进自己完成，插件不记账。
- **嵌套重入门卫（2026-10-05 实测修复）**：`CastSpell` 内部播施法动画（约 0.4~0.8s），动画期间游戏消息循环继续跑、0x4744D0 被再次调用，插件施法判定重入——此刻 `heroCasted` 置位（动画后才执行）与 `MarkHeroCastThisTurn_`（返回后才调）都未发生，挡板读到 0，同回合嵌套施出第二个法术（圣灵+迟缓同回合双施的根因，详见[战斗英雄一回合施法限制逆向笔记](<../../H3Note/战斗英雄一回合施法限制逆向笔记.md>) §5.1）。修法：`g_cast_in_flight` 门卫——三个通道的 `cm->CastSpell` 调用点前置置 true、except/正常两路复位；`TryProtectCast_` 入口判它短路重入。
- **施法方临时校正（2026-10-05 修复）**：`CastSpell` 内部全部按 `currentActiveSide`（0x132C0）口径执行（目标方 = `1-currentActiveSide`、单体路径重算 expertise、heroCasted 置位与耗魔同侧）；钩子时刻该字段滞后于行动方时群体法术整体错边不生效（迟缓连续两回合连施的根因，[同一逆向笔记](<../../H3Note/战斗英雄一回合施法限制逆向笔记.md>) §5.2）。修法：`CastSideGuardEnter_/Leave_` 施法前把 `currentActiveSide` 校正为玩家方、施完恢复。**约束**：施法类限制一律禁止依赖界面变化/动画/延时（游戏有加速功能），只允许同步读写游戏数据字段。
- 按各队方式（本节）在够格部队中选目标。全手动、单次接管时不判、不施。失败不挡部队动作和循环施法。

<a id="section-3-1-3"></a>
### 3.1.3 保持状态

方案级列表，在面板「保持状态」页用「+」逐项加入（最多 8 项）。候选项只取当前英雄已学会、且法术表标了全体增益标志（`friendlyMass` / `expertMassVersion`）的全体魔法；减速（54）单独作为敌方项，只有专家级才出现。没有全体版的法术（火盾、反魔法、魔镜、狂暴等）不进列表。

- **补的时机**（2026-10-05 用户定：多个全保持、谁先到期补谁；阈值玩家可调）：
  - **友方增益**（`ChooseBuffToRefresh`）：所有已配置项都参与保持——某项在任一存活部队上剩余回合 `<= 阈值`（`StatusProfileFields.refresh_turns`，面板可改 1..9，默认 1）即补；多个到期取剩余最短的那项（并列取列表靠前者）。全部部队都不需要时不施。
  - **敌方减速**（`ChooseSlowTarget`，语义 A）：按「全体覆盖」算达标——敌方已有**任意一队**带迟缓 buff（剩余 `> 阈值`）就**不再施**全群体迟缓；只有敌方没有任何一队被覆盖时才施。理由：敌方可能有抵抗术，部分命中是常态，若按「任一队缺失即补」会在被抵抗后连续多回合重复施放，挤占一回合一次的施法位与魔力。
- **剩余回合读取**：全体法术不逐队取最小或最大。对每个已配置法术，在目标侧找到**任意一队已经带有该状态**，就直接采用这一队的 `active_spell_duration[spell]`；因为是全体法术，各队剩余回合一致。若没有任何一队已有该状态，记 0，视为缺失。无法接受该法术的部队不参与判断，因此不会把已经生效的全体状态拖成每回合重放。接受条件按原版 `FUN_0044a1a0` 逐法术分开，不用 AI 价值：箭塔一律不收；法术带 `cannotTargetSiege` 时攻城器械不收；圣灵（41）不要亡灵，并且最高伤害为 0 的不收；幸运（51）、厄运（52）、杀戮（55）最高伤害为 0 的不收；欢欣鼓舞（49）、悲伤（50）无士气（`noMorale`）的不收；精准射击（44）只收射击部队。护盾、石肤、祈愿、加速、减速等没有额外生物类排除。目标侧一个可接受的存活部队都没有时，代表回合记 -1，**不调用施法**（原版会弹出阻止框），也不占本回合。**不拿 `0x4477A0` 当门卫**：它混合了“已带检查”和 AI 施法价值评估。若施放后目标侧仍没有任何存活队获得持续时间，置 `g_status_immune_mask` 本场跳过整个法术。
- **免疫**：等级不够或本身免疫的部队记 -1，不参与剩余回合比较与覆盖判定，也不会因此触发补状态。
- **全体施放**：这些法术都是全体魔法，`CastSpell` 不指定目标格（hex = -1，cast_type = 1）。友方增益覆盖己方，减速覆盖敌方。施法同样走 [§3.1.1](<#section-3-1-1>) 的 `g_cast_in_flight` 门卫与 `CastSideGuard` 校正。
- 未学会、法力不足、本回合已施法时跳过。玩家方没有英雄时本通道与保活、召唤一起关闭。

<a id="section-3-1-2"></a>
### 3.1.2 自动停止（敌方预计回合）

打铁跑着时，按最近两笔取样之间的掉血速度估计敌方还要几回合全灭。预计回合数不大于玩家设的阈值时，切到全手动并把控制权交回玩家。

- **阈值（方案级）**：停止行最右侧 `停止: [数字]`，范围 0..999，默认 4（2026-10-06 由 10 调低：小怪战斗一回合外推就 ≤10 必停，玩家体感"只打一回合就停"）。0 = 关闭。随 5 套方案各自保存、切换、提交。
- **按数量阈值（部队级）**：每张部队卡片「保活:」下拉选「剩余数量≤」时显示 `剩≤ [数字]`（默认 2，范围 0..2147483647），逐队各自保存；仅该方式参与判定（不保活/损失量方式下不显示）。
- **血量**：敌方每个存活槽的 `存活数 × 单兵满血 − 顶层已损`。箭塔、弩车、急救帐篷、投石车、弹药车不计入。
- **取样**：每个战斗回合只记一次，只保留最近两笔。两笔之间掉血为 0 或敌方总血量变高（召唤、复活）时，丢掉旧笔、从当前重新计，不判。
- **判定**：最近两笔 `经过回合 > 0` 且 `掉血 > 0` 时，预计剩余回合 = `当前血量 × 经过回合 / 掉血`（向上取整）。`预计 <= 阈值` 才停。不足两笔、或阈值是 0，不停。
- **停的方式**：控制权切到全手动（`g_control = CM_MANUAL`，与按启停热键切到停相同），清掉未完成的单次接管。当前这次行动不再代发。之后玩家可再按热键启动。
- **第二条件（敌方魔力）**：保活行「[✓] 敌方魔力≤[框] 时停」组合（方案级 `g_summon[p].stop_enemy_mana` 勾选 + `stop_mana_th` 阈值框，**默认勾选**、阈值默认 6，0..32767 可调、随方案存档）。勾选时敌方英雄**存在且有魔法书**（`DoesWearArtifact(0)`）且剩余魔力 ≤ 阈值 → 与停止回合数 OR 组合，任一触发即停（同款切手动，日志 `[AutoStop] enemy mana low`）。无书英雄魔力常为 0，不判书会开战即误停；每次控制权交还玩家都判，不受回合取样约束。
- 全手动、设置面板打开时不取样、不判。重打或战斗状态重置后两笔取样作废。

<a id="section-3-7"></a>
### 3.7 兵力不足时召唤（召唤兜底通道）

力盾、保活、保持状态与召唤是**同一条施法通道**（缺盾优先，其次保活、保持状态，最后召唤）：玩家方没有英雄时整条通道不走。有英雄时，每次行动（还有施法次数时）先补配置落点的缺失力盾，再按各部队的保活方式判保活（[§3.1.1](<#section-3-1-1>)），没人该救再判保持状态（[§3.1.3](<#section-3-1-3>)），仍不施法且召唤已启用（方案级 `g_summon[p].enabled`，默认不启用）才判召唤。一回合英雄只施一次法。召唤参数在面板「召唤」页配置（[§8.8](<06-设置面板与输入绘制.md#section-8-8>)）：

- **启用**（`enabled`，方案级，默认 0）：召唤页「启用自动召唤」勾选框，与全局「停止:」同一行。不勾＝只保活、不召唤。
- **时机**：存活的本体部队（军队槽 0..6）加存活的召唤物（四系元素，克隆与战争机器不计）**严格小于** `count_th`（默认 2，范围 2..21）、剩余血量合计（各队 `存活数 × 单兵满血 − 顶层已损` 加总，同口径）≤ `hp_th`（默认 750），两条件按 `cond_combine`（0=和，默认；1=或）组合判定——「和」＝都满足才施放、「或」＝任一满足即施放；不满足静默跳过、不记失败。事件型判定（每次控制权交玩家都判），`hero_casted` 挡施（`TryProtectCast_` 共享守卫已查，`SummonChannel_` 内再自查法力/已学）。
- **法术选择**（`spell_pick`）：0=自动 → 已学四系（气 69/水 68/火 66/土 67）中单次召唤总量最大者（平手取靠前），**首次成功施放后本场锁定**（`g_summon_locked_spell`，战斗结束/重打清空）；1..4=固定该系，未学则整场不召。
- **施放**：`CastSpell(spell, 锚定格, 0, -1, GetSpellExpertise, power)`，SEH 包裹；锚定格暂取己方第一支存活部队所在格（target hex 实参语义列 [§11](<11-验证边界与待办.md#section-11>) 上机验证）。法力消耗 15、召唤量=力量×等级系数（基础 2/高级 3/专家 4）为暂定口径，上机对拍后修订常量表。施法同样走 [§3.1.1](<#section-3-1-1>) 的 `g_cast_in_flight` 门卫与 `CastSideGuard` 校正。
- **生效判定**：`cast_ok` = 法力下降（`mana_now < mana_before`）**或** `hero_casted` 翻转（`casted_before == 0 && casted_now != 0`）；只有 `cast_ok` 才补写 `hero_casted` 并在自动模式记锁定，槽位占满等静默失败不记。
- **召唤物行动**（共享规则 `g_summon[p].summon_rule`，全部召唤物一条，**默认防御**）：手动 / 防御 / **散开**（对档位 d∈{2,1}：可达格中找与己方其它所有存活部队（含战争机器）距离均 ≥d 的格，取「最小距离」最大者；当前格已达标则不动；两档均无 → 原地防御，降级链固定终于防御）/ **随机移动**（可达格不含当前格均匀随机；无可达格或提交失败按「允许降级为防御」勾选降级或交回玩家）。距离为战场六格坐标距离（`HexCoordDistance`，15×11 odd-r 立方坐标）。行动集经 `NormalizeSummonRule` 裁剪（清目标/施法/保活字段，降级勾选仅随机移动保留），普通部队行动下拉不出这两项。
- **动态接管**：召唤物上场后由 `UpdateStackTracking_` 动态补绑（仅召唤启用时）：身份 `STACK_ID_SUMMON` + 四系元素 + 槽未绑定 → 绑定跟踪条目并套共享规则，之后走现有行动管线。克隆物（`clone_id>0` 且非四系）不绑、保持手动。绑定/首绑时刻已在场的召唤物同样套用共享规则。
- **保活优先**：保活候选（按各队 ProtectMode 判定，「不保活」永不入选）非空时必救、不召唤；法力 <10（复活/聚灵耗魔）且有人该救时两边都不施；召唤物召唤后队数 +1，条件自然关闭。

<a id="section-10-4"></a>
### 10.4 快捷施法执行

**实现**：UI 为 `spellSlots[10]` + `spellSlotCount`（兼容旧 `spellSlot` / `quickCastFirst`）；运行游标在跟踪表 `spell_cursor`。执行端即单位行动管线（`g_pipeline_stage`，[§15.2](<05-战斗生命周期与控制权.md#section-15-2>)）：

1. `PS_IDLE`：控制权交给玩家时，若序列非空、管线空闲、本回合该单位未施过，投递快捷键 `1-9/0` → `PS_SPELL_POSTED`（本帧不提交部队动作）；
2. `PS_SPELL_POSTED`：观察 `hero_casted` 翻转（`casted_now != 0 && casted_before == 0`）**或**法力下降（`mana_now < mana_before`），超时 2000ms 按真实时间（`GetTickCount`；`BltComplete` 一毫秒内可触发多次，不能按调用次数计时）→ 推进游标、清投递 → `PS_SPELL_DONE`（无论成败都不重投）；
3. `PS_SPELL_DONE`：施法阶段结束，提交该部队主动作（主动作为手动时仅施法后交回玩家）→ `PS_HANDLED`；
4. `PS_HANDLED`：本回合已处理（含降级失败交回玩家），不再重复下命令；活动单位变化时管线整体回 `PS_IDLE`。

管线锚定 `g_pipeline_stack`（活动单位）；英雄本回合已施过法时直接进 `PS_SPELL_DONE` 跳过投键。

- **士气高涨（同部队立即再激活）**：额外行动发生时没有其它部队插入，活动单位不变，原来「单位变化才复位」清不掉 `PS_HANDLED`，第二次行动会被挡住。修复分两层：
  - **识别**：`SubmitDefend_`/`WriteAction_` 写入命令时置 `g_pipeline_action_landed`。`HH_ShouldAutoExecute`（0x4744D0 控制权判定点，战斗动画期间不被调用）使用 `CurrentTurnStack_`，不能使用经常为空的 `active_stack`。检测「同一当前部队 + 命令已落地 + `action` 已被执行器清 0」即判为全新一次行动机会，复位 `PS_IDLE`。分类读取该部队 `creature.flags@0x84` 的 bit24：**仍置位 = 士气额外行动**（置 `g_pipeline_morale_extra`）；**已清除 = 新回合**（极端情况：场上只剩一支部队、回合背靠背，单位变化复位同样触发不了）。依据是 `FUN_00464500` 在士气成功时置 bit24 并请求下一次控制权，而真实新回合的 `FUN_00446e40` 用 `0xF8FFFFFF` 清掉 bit24/25/26。`turn` 每次行动入口都加一，不能分类；`BattleMgr+0x132A0` 是魔幻法师施法间隔，也不能当通用回合计数。使用士气标记时重新核对 bit24。快捷施法由 `hero_casted` 挡住不会二施；交回玩家类 `PS_HANDLED` 未落地命令，不参与复位。
  - **语义（循环作用于回合，不作用于同回合的额外行动）**：`SubmitConfiguredUnitAction_` 在 `morale_extra` 窗口内——循环移动 → 无条件原地防御（不受“允许降级为防御”控制；路径游标已在本回合正常推进，下回合走下一点）；循环近战 → `SubmitMelee_` 带 `repeat_pair`（游标回退一格取本回合刚打过的组合）重打且**不推进游标**；其余动作（远程/急救/防御/召唤物走位）无回合游标，自然再执行一次。所有管线复位点（单位变化 ×2、单次接管、`ResetAutoState`）同步清 `landed`/`morale_extra` 标记。

力盾、保活、保持状态与召唤插在管线之前，同一条施法通道（`TryProtectCast_`，**保活优先，其次保持状态**）：守卫（战斗中·面板关 + 控制权自动 + 英雄本回合未施法）通过后：

缺盾补施先于以下保活/状态/召唤流程；已经施法则由游戏字段挡住后续分支。

1. 遍历己方部队槽（跟踪表校验人类侧身份 + 开战前数量 > 0；战争机器排除）：按其生物 `undead` 标志定法术（聚灵 39 / 复活 38），取该法术当前等级的可恢复量（法术表 `baseValue[等级] + 力量 × spEffect` 加英雄法术特长；复活与聚灵同一算法，读不到表时退回 50/75/100×力量），按**该队自己的保活方式**（`protectMode`）判定是否够格：剩余数量≤ → 剩余数量 ≤ 该队「剩≤」阈值（全灭数量 0 天然满足，仍要求有尸体格）；损失量大于恢复量 → 已损血量（死亡数×满血＋顶层已损，全灭即满损失）严格大于可恢复量。死亡数的基准是英雄战前军队数量（`H3Hero::army`，与读档关联同一份）。无损失（已损 = 0）永不触发。够格者入候选。
2. 候选非空 → 法力 ≥10（复活耗魔门槛）才施放：调 `H3CombatManager::CastSpell`（`0x5A0140`，`cast_type` 实参 0=单体施法，语义为逆向推断）直接施放（目标=候选中剩余血量最低者所在格，`SelectProtectTargetIndex`），不占快捷施法、不推进任何部队的循环施法游标。法力不足静默跳过。施法前置 `g_cast_in_flight`、经 `CastSideGuardEnter_/Leave_` 校正施法方（[§3.1.1](<#section-3-1-1>)），成功后 `MarkHeroCastThisTurn_` 补写玩家方 `hero_casted`。
3. **候选为空** → 先判保持状态 `TryMaintainStatus_`（[§3.1.3](<#section-3-1-3>)，友方增益/敌方减速按各语义判）；仍不施**且召唤已启用**（`g_summon[p].enabled`）→ 转召唤兜底 `SummonChannel_`（[§3.7](<#section-3-7>)：自查法力/已学，`PickSummonSpell` 选系，`SummonShouldCast` 判时机，`CastSpell` SEH 包裹施放，`cast_ok`（法力下降 ∨ casted 翻转）且自动模式记 `g_summon_locked_spell`）；未启用或阈值未到则什么都不施。
4. 条件不满足、无人勾选、法术没学、法力不足或英雄已施法：本回合记为已判，直接进入上面的循环施法。
5. 若当前部队主动作为手动：保活施法结束后交回玩家，与「只配了循环施法」相同。

复活与保持状态与召唤都是**事件型**，每次控制权交玩家都判（[§3.1.1](<#section-3-1-1>)/[§3.1.3](<#section-3-1-3>)/[§3.7](<#section-3-7>)），已施法（游戏字段 `heroCasted[side]`，见 [§3.1.1](<#section-3-1-1>)）静默跳过；一回合只施一次法，三分支天然互斥。

保活与自动停止的入口守卫：仅「战斗中·面板关 + 控制权为自动」时判定（[§3.1.1](<#section-3-1-1>)/[§3.1.2](<#section-3-1-2>)）。`TryAutoStop_` 在保活之后、快捷施法管线之前执行：先判敌方魔力条件（勾选且敌方英雄有魔法书且魔力 ≤ 方案阈值 `stop_mana_th` 即停，不受回合取样约束），再走回合投影（取样/外推，阈值 0 跳过）；两者任一命中同款切手动。
