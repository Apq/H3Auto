## 输入屏障生命周期修复（2026-10-06）

重打会析构旧 BattleUI/item，且新窗口可能复用同一地址。关闭面板后不再保留
`BattleInputBlocker` 的旧 item 引用；旧控件还原虚表/隐藏，所有权仍在游戏。
任何还原/隐藏前先在当前活动 BattleUI 的 `GetList()` 查到 item 指针，之后才读取
parent/id/vtable。仅比较 `battle_ui` 指针相等不能授权写旧控件。
`AddItem` 先接管 item 到 owned vector，初始化返回不当作 BOOL 成功标志；
加入后不会自行 DestroyItem 导致窗口向量含悬挂项。首次打开若安装失败，
取消打开并 Close 清理，不允许无输入屏障继续绘制或进入点选。

22:59 崩溃的 HD 原始栈位于障碍 DEF 释放后的资源树删除；fault 节点 `080B3D20`
和重打后被错误触碰的旧屏障一致，节点首 DWORD `0x63BA24` 正是透明控件虚表。
这是旧屏障引用写坏资源树的高置信证据链，未做首次写入断点或实机复测。
纯归属回归不代表原版生命周期已验证；详见
[窗口逆向笔记](../../H3Note/H3Auto设置对话框逆向笔记.md)。

Compat 装备查询入口同步纠正为 `0x4D9460`、返回 BOOL32；`0x4E2C90` 是
GiveArtifact 函数内部指令而非入口。此独立问题不能解释为已证实的 ESP 污染。
未修改 ForceField 的用户指定无预检、无首盾捕获、两落点保持规则。
