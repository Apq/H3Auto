## 10. 执行分发（源：[AutoExecute.inc.cpp](<../modules/AutoExecute.inc.cpp>)）

<a id="section-10-1"></a>
### 10.1 接管判定（`DecideTakeover`）

回放/隐藏战斗（`IsHiddenBattle`）一律 `CD_KEEP_ORIGINAL`。战术布阵阶段不接管。

**最高优先级：人工控制门**（控制权子状态 `g_control`，[§15.2](<#section-15-2>)；不改 5 套方案、不推进任何循环游标）：

| 模式 | 热键（INI `[Hotkeys]`，可改） | 行为 |
| --- | --- | --- |
| 全手动 `CM_MANUAL` | `ToggleManual=F9` 切换 | 本场所有已配置部队都把控制权交回玩家，直到再按一次恢复自动 |
| 单次接管 `CM_ONESHOT_WAIT/LOCKED` | `OneShotManual=J` 边沿触发 | 锁定当前（或下一支）人类侧部队；该部队完成一次**玩家**动作后自动恢复 |
| 打开设置 | `OpenSettings=P` 边沿触发 | 仅战斗中·面板关响应；打开即切全手动并清施法等待（[§15.3](<#section-15-3>)），与右键自动战斗按钮同一条打开边 |

保存方案（面板「确定」）只落方案并进入**全手动**，不立即自动执行；按 `F9` 启动自动。**2026-10-06 修正：所有进场（进程启动、新战斗、取消重打、读档兜底、接受结果）一律默认全手动，自动执行只能由 `F9` 显式启动**——修复"上一场 AUTO 中读档/重打，方案保留 + 控制权残留 AUTO，还没按 F9 一进战斗就自动打"。`J` 单次接管结束后回到按 `J` 前的模式（AUTO 中按回 AUTO、MANUAL 中按回 MANUAL），不再固定回 AUTO。

约束：

- 若当前已有插件提交中的施法/近战等“飞行中”动作，单次接管延后到下一支（`CM_ONESHOT_WAIT`），绝不半途打断。
- 热键按下由常驻 WH_KEYBOARD 线程钩子捕获（keydown 边沿、滤自动重复），挂回合控制权判定的轮询只消费标志——战斗动画期间轮询不运行也不漏按。战斗结束边（接受/兜底）会丢弃未消费的热键标志，不跨场残留。
- 设置面板打开时钩子不捕获这三枚热键。
- 单次接管绑定当前尝试中的 `side + army_slot_ix + creature_id`，松键不会丢锁定；真正消费以 `0x4786B0` 执行玩家动作为准。它是本轮人工接管的运行时校验，不是跨重打的配置身份。
- 单次接管、打开设置键只允许单个字母，禁止 F1–F12、数字、Ctrl、Alt、Tab、Shift；打开设置键另排除战斗占用集（[§15.4](<#section-15-4>)）。
- 状态提示：`打铁助手: 自动 / 全手动 / 单次接管 / 单次待命`。

否则按单位类型判定：

| 单位    | 判定                        |
| ----- | ------------------------- |
| 弹药车   | 保持原版                      |
| 急救帐篷  | 配了急救→执行；否则有急救术→原版，无→交 AI  |
| 投石车   | 防御→代为防御；其余保持原版（手动） |
| 弩车/箭塔 | 远程→执行；有炮术且手动→原版；其余交 AI |
| 普通部队  | 手动且无循环施法→保持原版；有非手动主动作或配置了循环施法→按配置执行（仅施法阶段后交回玩家；绝不交回 AI） |

## 15. 战场状态机（已实现）

插件的控制流以三层状态机组织：顶层战场生命周期（本节 15.1）、控制权子状态与单位行动管线子状态（15.2）。所有迁移走唯一出口 `SetPhase_(next, ev)`（实现在 [BattleState.inc.cpp](<../modules/BattleState.inc.cpp>)，类型与声明在 [BattleState.hpp](<../modules/BattleState.hpp>)）：合法边查表 → 边动作 `PhaseEdgeAction_(from, ev)` → 写 `g_phase` → `[Phase]` 日志；非法组合记日志并保持原状，幂等（同状态重复事件不算迁移）。

<a id="section-15-1"></a>
### 15.1 顶层状态与迁移

```cpp
enum BattlePhase {
    BP_PEACE,          // 战斗前
    BP_COMBAT_CLOSED,  // 战斗中·面板关
    BP_COMBAT_OPEN,    // 战斗中·面板开
    BP_RESULT,         // 战斗结算
    BP_ENDED,          // 战斗结束（瞬态：进入即清理，随即续转 BP_PEACE）
};
```

合法迁移边（查表）：

```text
战斗前 ──战斗UI出现──> 战斗中·面板关
战斗前 ──结果窗出现──> 战斗结算           （快速战斗：从未出现战斗 UI）
战斗中·面板关 ──右键自动战斗/P键──> 战斗中·面板开   边动作：强制停（15.3）
战斗中·面板开 ──确定──> 战斗中·面板关    （提交方案；已停，等 F9）
战斗中·面板开 ──取消/ESC──> 战斗中·面板关 （丢弃草稿；已停，等 F9）
战斗中·面板关/面板开 ──结果窗出现──> 战斗结算（面板开时强制关面板）
战斗结算 ──取消/重打──> 战斗中·面板关    边动作：重排+重绑+清运行时，方案保留，置 3000ms 重打宽限
战斗结算 ──接受──> 战斗结束              边动作：清方案+运行时+跟踪，控制权回全手动
战斗中·面板关/面板开/结算 ──UI消失且未经结算──> 战斗结束（兜底边，方案保留，控制权回全手动）
战斗前 ──取消/重打──> 战斗中·面板关        （UI_GONE 抢跑补边，2026-10-05 加）
战斗前 ──接受──> 战斗结束                  （同上；边动作幂等补执行）
战斗结束 ──（瞬态续转，沿用进入事件）──> 战斗前
```

- **UI_GONE 抢跑竞态**（玩家日志 2026-10-02 实测暴露，46 次重打/25 次接受被拒）：玩家用键盘（ESC/回车）关结果窗时点击捕捉不到 armed，Life 层要等 1500ms 宽限才裁决，而 UI_GONE 的 3 帧检测 ~100ms 就把结算推到战斗前，随后重打/接受事件到达被拒、边动作丢失——重打后跟踪不重绑 → 全场 `[Track] takeover mismatch`、自动规则失效；接受后方案残留。修复三层：
  1. **结果窗意图未裁决期间 UI_GONE 兜底退位**：`s_saw_cpresult` 为 true 时不触发兜底边（`CheckAutoFightDialogClosed`），意图事件独占裁决权；
  2. **裁决必然发生**：未捕获点击 1500ms 宽限（`RESULT_CLOSE_GRACE_MS`）后按无战斗 UI 收场裁决；取消已按但战斗 UI 8000ms 不回（`RESULT_ABORT_TIMEOUT_MS`，如结果窗上直接退出）强制按终局裁决，防退位后卡死在结算态；
  3. **补边兜底**：万一状态仍被推到战斗前，补两条 `战斗前 ──取消/重打/接受──>` 合法边，边动作按事件分发幂等补执行（重打重绑/接受清方案）。

- **战斗结束是瞬态**：无驻留时间、无自己的事件，进入即清理后自动续转「战斗前」；保留为独立状态是为了清理动作有归属、日志可读。续转边（`from == BP_ENDED`）不执行任何边动作——清理只在进入 ENDED 的主边做一次，不依赖边动作幂等。
- **事件源**：BltComplete 每帧扫描——战斗 UI 出现（虚表判定）、UI 连续缺失 ≥3 帧（兜底边；重打宽限 `g_ui_gone_grace_until` 3000ms 内不触发，防 UI 重建误触；结果窗意图未裁决期间 `s_saw_cpresult` 退位不触发，见上方竞态说明）、P 键标志消费；`CheckBattleResultLifecycle_`——CPResult 结果窗出现/接受/取消（归并成 `BE_RESULT_SHOWN / ACCEPTED / RETRY` 三事件）；面板鼠标钩子与消息入口——面板开关。
- **守卫不进顶层**（满足外部形态与行为变化但无进出清理动作）：战术布阵（tactics）、隐藏战斗（`0x46A080`：快速战斗/AI 对打/回放）、原版 `auto_combat`、游戏非前台。这些在执行链入口以条件判定挡住。
- 旧散落判断的归并：`IsPanelActive` 等价于 `BP_COMBAT_OPEN`（面板真实开态仍查 `s_p.active`）；执行/保活/自动停止入口统一守卫 `g_phase == BP_COMBAT_CLOSED`。

### 15.2 子状态（战斗中·面板关内）

**控制权 `g_control`**（取代旧 battle_manual / oneshot_active / oneshot_pending 三标志）：

| 模式 | 含义 | 进入 | 离开 |
| --- | --- | --- | --- |
| `CM_AUTO` | 自动执行 | F9 显式启动；AUTO 中按 J 后单次接管完成返回 | F9 切换、J 锁定、打开面板、保存方案、自动停止触发 |
| `CM_MANUAL` | 本场全手动 | 默认进场；F9 停止；打开面板、保存方案、自动停止、重打、接受及兜底边 | F9 显式启动自动；J 临时接管完成返回按下前模式 |
| `CM_ONESHOT_WAIT` | 单次接管待命（无可锁部队或有飞行中动作） | J 按下且暂不可锁 | 下一支可锁部队出现→LOCKED；切 MANUAL/AUTO 清 |
| `CM_ONESHOT_LOCKED` | 单次接管锁定中 | 待命的部队出现，或 J 时恰有可锁部队 | 锁定部队完成一次玩家动作（`0x4786B0` 确认）或活动单位已变→按 J 前模式 |

用户可见切换（F9/J/面板打开/边动作）一律走 `SetControlMode_`（日志 `[Control] control=…` + 状态提示刷新）；自动停止触发同样经它切 `CM_MANUAL`（另有自带中文日志）。锁定目标数据（side/slot/creature/指针）仍在 `g_auto_state`，`ClearOneShotManual_` 只清数据，模式由调用方归位。

**单位行动管线 `g_pipeline_stage`**（取代旧 spell_waiting / spell_wait_stack / spell_done_stack / last_handled_stack 四标志；详见 [§10.4](<03-英雄施法与自动停止.md#section-10-4>)）：

| 阶段 | 含义 |
| --- | --- |
| `PS_IDLE` | 当前单位无未完成管线 |
| `PS_SPELL_POSTED` | 已投递快捷施法键，等待结果（超时数据在 `g_auto_state.spell_wait_*`） |
| `PS_SPELL_DONE` | 本单位本回合施法阶段已结束，不再投键 |
| `PS_HANDLED` | 本单位本回合已处理（已下命令或交回玩家），不再重复处理 |

管线锚定 `g_pipeline_stack`（当前部队）；复位集中在 0x4744D0 控制权判定点，统一按 `CurrentTurnStack_` 判断：当前部队变化、同一部队且士气标志已清的新回合、同一部队且士气标志仍在的额外行动（`g_pipeline_morale_extra`）都整体回 `PS_IDLE`（[§10.4](<03-英雄施法与自动停止.md#section-10-4>)）。`ClearSpellWait_`（撤销投递）把 POSTED→DONE 且保留锚定单位，防同回合重投；彻底清零由 `ResetAutoState` 与单次接管清单位负责。`action_wake_stack`（投递唤醒消息等待提交）保留原样——它是投递细节而非回合状态。

**面板开内的子模态**（帮助弹窗、快捷键录入、近战拾取隐藏态、停止数字录入）不入状态机，由面板自身的模态计数器管理（[§8.0](<06-设置面板与输入绘制.md#section-8-0>)）。

<a id="section-15-3"></a>
### 15.3 打开边的强制停（关键决策）

进入「战斗中·面板开」的边上**必须已停止自动执行**——不做前置拒绝，而是打开同帧强制：

1. 切全手动：`SetControlMode_(CM_MANUAL)`（与 F9 同一条清理路径）+ `ClearOneShotManual_()`；
2. 清施法等待：`ClearSpellWait_()`（`GetTickCount` 相对超时挂在面板关闭后会瞬间误超时，故清空而非冻结；管线 POSTED→DONE，该单位本回合不再重投）；
3. 再开面板：右键路径与 P 键路径都是先 `OpenSettingsPanel_()`、`s_p.active` 置位成功后才 `SetPhase_(BP_COMBAT_OPEN, BE_PANEL_OPEN_REQUESTED)`——杜绝「已迁移但面板没开」的死状态。

连带简化：面板「确定」的 `CommitProfiles → Pause → Close` 中 `Pause` 退化为幂等保护。唤醒等待（已投递的鼠标移动）无害可保留；单次接管随切停清除，属有意行为（改完设置本就要 F9 重启）。切停前一帧已投出的快捷键消息仍会到达，面板开时 `Hook_BattleMsgProc` 吞数字键已覆盖。全手动下战斗仍会推进到结算，「面板开 → 结算」边保留。

<a id="section-15-4"></a>
### 15.4 打开设置热键

- INI `[Hotkeys] OpenSettings=P`（默认）；解析复用 `ParseHotkeyVk_`（letter_only），校验 A–Z 且排除战斗占用键集 `A C D E H I L O Q R S T W`（原版/HD/HotA 战斗键）+ 本插件 `J`（`IsAllowedOpenPanelVk_`），与 `OneShotManual` 相同时也回退 P，记日志。单次接管键（`OneShotManual`，默认 J）走 `IsAllowedOneShotVk_`：只要求 A–Z 且排除 `E`（`vk >= 'A' && vk <= 'Z' && vk != 'E'`），不套用上面那组战斗占用键。
- 处理链与 F9 同构：常驻键盘钩子只置 `kb_open_panel_seen` 标志（面板开时不捕获），BltComplete 的「战斗中·面板关」分支消费；消费即走 15.3 打开边（与右键同一条边动作）。
- 战斗结束边（接受/兜底）丢弃未消费的标志，不跨场残留；帮助弹窗热键行从当前配置生成三键说明。
