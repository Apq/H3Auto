## 17. 战斗内容指纹与智能存读档

目标：给每场战斗一个稳定标识——重打、战斗中读档 S&L、关游戏再开，同一场战斗得到同一个值；并以此为核心做**智能存读档**：点√自动存档、开面板自动载草稿、下拉框选历史档（打铁常遇同一敌情反复刷）。

<a id="section-17-1"></a>
### 17.1 指纹定义（PolicyCore `ComputeBattleFingerprint`）

FNV-1a 64 逐字段滚动，全部喂「开局态」（重打/S&L 后回到同一快照的数据）：

| 分量 | 来源 | 稳定性说明 |
| --- | --- | --- |
| 双方各 ≤21 槽 (生物类型, 开局数量) | `mgr->stack[s][i].creature_id / count_at_start` | 按 (type,count) 升序排序后喂入——与内部槽位顺序、左右镜像无关；`count_at_start` 不受战斗推进影响 |
| 双方英雄 id | `mgr->hero[s]->id`，无英雄 = -1 | 地图固定后 id 跨 S/L/重启不变；不含技能/法术（变化太频繁） |
| 战场地形 / 攻城类型 | `mgr->land_type / siege_kind`（0x5394/0x53A4） | 战斗开局固定 |
| 冒险地图触发点 (x,y,z) | [§17.2](<#section-17-2>) 推导 | z 区分地上/地下；取**被攻击方**位置——同一目标从不同方向攻击仍是同一场，故不用攻击发起格 |

侧序号参与哈希：攻守互换（玩家被怪撞 vs 玩家主动打野怪）算不同战斗。空槽（type≤0 或数量≤0）不参与。碰撞（同指纹不同战斗）后果只是把上次方案带进本场——同敌情方案通常仍适用，且下一次「确定」即覆盖自愈。

<a id="section-17-2"></a>
### 17.2 触发点坐标推导（AutoExecute `ResolveBattleMapCoord_`）

三层依次取用，全部零地图 API（官方 `H3CombatManager::mapitem`@0x53BC 虽存战斗发生格对象，但 `GetCoordinates` 是 H3API.dll 导入，本项目裸结构取不到坐标）：

1. **守方英雄格**：`mgr->hero[1]` 存在（守方有英雄：英雄对撞、守城有守将）→ 直接读其 `x/y/z`（`_Hero_` 头部 0x00/0x02/0x04，INT16）。
2. **人类英雄计划目的地**：`dest_x/y/z`（0x35/0x39/0x3D，INT32）与英雄当前位置**相邻**（切比雪夫 ≤1 同层）→ dest 即被攻击对象格。主动打野怪、攻城、访问资源触发战斗都成立；同一目标换方向攻击 dest 相同（这正是「用被攻击方坐标」的原因——攻击发起格随方向变化，dest 不变）。
3. **人类英雄格兜底**：被野怪/敌英雄主动撞击时，dest 是残留的旧目的地（不与英雄相邻），战斗触发点=英雄自身格。

`_Hero_`/`_BattleMgr_` 补字段后加 `#pragma pack(1)`：默认对齐下 `int id` 声明在 0x1A 实际落 0x1C，所有偏移以 pack 后为准（pack 前后 `spell_points`@0x18 等既有使用点偏移不变，无行为变化）。

<a id="section-17-3"></a>
### 17.3 智能存读档时机（挂 [§15](<05-战斗生命周期与控制权.md#section-15>) 状态机）

- **算指纹**：`BE_BATTLE_UI_APPEARED` 边动作（新战斗 UI 出现）→ `OnBattleAppearedFingerprint_()` 只采集+计算+记日志 `[Battle] 指纹=0x… 触发点=(x,y,z) 地形=… 攻城=…`，**不读库不生效**（不打面板=空方案是有意行为）。重打仍是同一场：`BE_RESULT_RETRY` 若本进程已经有指纹，不重算；若还没有（插件在结果窗期间才加载，或快速战斗后直接重打进入战斗 UI），补算一次，否则面板读不到本场存档。快速战斗停在结果窗、没有重打时仍不算指纹。
- **自动载草稿**：打开设置面板（`OpenSettingsPanel_` 草稿快照之后）→ `RefreshBattleRecordsAndAutoload_()` 读本场存档列表填下拉框；若本场已有存档**且本会话未载入过**（`s_battle_loaded_fp != 当前指纹`）→ 自动把**当前选中项**载入草稿（只改界面，不 `CommitProfiles`，点√确定才生效）。重打/战斗中 S&L 后再开面板：指纹相同且已载过 → 不重载（内存与草稿现状保留）。进程重启后同一场战斗：`s_battle_loaded_fp=0` → 首开面板照常自动载。
- **选中项记忆**：下拉框选中项随「确定」写入进程内存（`s_battle_sel_fp` + `s_battle_sel_time`，记选中档的**时间戳**而非下标——新档追加到末尾不影响旧时间戳）。下次打开同指纹面板按时间戳找回对应条并恢复选中；时间戳已不在列表（被淘汰）或换了战斗指纹 → 默认最新（0）。不落盘，进程重启归零。内容未变不新增记录时选中档保持；内容变了新档即新选中项。
- **存档**：每次面板「确定」（`CommitProfiles` 尾部）`AppendBattleStoreRecord` 把提交后的 5 套+激活号+当前时间戳追加进本场存档库；**与文件里最后一条内容相同（忽略时间戳）则不新增**；接受结果（`ClearConfirmedProfiles`）不动存档文件。

<a id="section-17-4"></a>
### 17.4 战斗存档库（ConfigLog + SettingsDlg 下拉框）

- **文件与目录**：`<游戏根>\Games\<地图名>\Auto\<16 位十六进制指纹>.json`，每场战斗一文件。目录读取 HD 游戏名链 `*(char**)(*(DWORD*)0x699538 + 0x1fb40)`；NULL/空白用 `Unnamed`，清洗路径分隔、控制字符及非法字符；链不可读退 `Games\Auto`，无 Games 根退 DLL 同目录。旧 DLL 同目录档不迁移。
- **生产 JSON v4**：根为 `{"version":4,"battle":"<hex16>","entries":[…]}`，只接受 v4 且指纹匹配；entries 按时间升序。每条包含 `time`、`active`（1..5）、`profiles[5]`。每套包含 `stopTurns`、`summon`（enabled/count/hp/spell/combine/stopEnemyMana/mana/rule）、`army`（非默认槽的 slot/rule）、`status`（buffs/slow/refreshTurns）、`forcefield`（anchor_hex 两整数数组）。力盾对象严格验证，不兼容旧根版本。
- **实现边界**：[ConfigLog.inc.cpp](<../modules/ConfigLog.inc.cpp>) 使用 nlohmann/json 3.11.3 单头文件（`JSON_NOEXCEPTION`，解析允许注释）。只写非默认 army 槽；读前将 21 槽设为默认，再按保存槽号载入，同指纹不做四轮部队关联。旧数字串和解析失败当无存档，不迁移；大路径缓冲在堆上，读写入口包 SEH。H3AP9 是独立纯文本接口，不是生产 JSON 载荷，见[格式演进历史](<历史/方案存档格式演进.md>)。


- **条数上限**：每文件保留最近 30 条（追加时满 30 丢最老，`AppendBattleStoreRecord` 内重写整文件）；跨文件再按 mtime LRU 保留最近 30 场（`PruneBattleStore`，只匹配 16 位 hex + `.json` 文件名，目录里其它 json 不动；列目录/删除走宽字符 API——目录含中文地图名，`FindFirstFileA`/`DeleteFileA` 按 GBK 误读 UTF-8 路径会静默查不到，旧版在中文 DLL 目录里因此从未实际淘汰）。
- **UI**：原「读档」「存档」两按钮合并区（右上 `?` 左侧）改**本场存档下拉框**，样式与召唤/卡片下拉统一：按钮底色 74,52,24（展开/按下 104,70,28）、金框 210,170,72、右侧金色像素三角箭头（收起▼/展开▲）、文字金色左对齐，显示当前选中档时间/「本场存档」/「无存档」。展开列表时间**降序**（0=最新），行内容 `yyyymmdd-hhmmss  P<方案号>`，每项独立底色+边框（悬停 184,136,48 / 选中 136,88,24 / 普通 68,42,18），选中项金色文字（WH_MOUSE 钩子同保活下拉）。点历史档 → `LoadBattleRecordIntoDrafts_` 立即载入草稿（收尾同旧读档：取消录入/收起下拉/重绑可见行），点√确定才生效。旧 profiles1-5.ini 手动存读档入口已移除（磁盘文件不删）。
- **去重口径**：`BattleStoreRecordContentEquals`（PolicyCore 纯函数，含 5×21 规则 + 停止回合 + 召唤参数（含启用位）+ **保持状态 `status[5]`**（`slots`/slot_count/slow/refresh_turns）+ **两落点力盾 `forcefield[5]`** + 激活号，忽略时间戳）；字节级比较，两侧均零初始化（`= {}`/`new T()`），padding 不产生假阴性。

<a id="section-17-5"></a>
### 17.5 已知限制

- 唯一性依赖开局态：同一玩家军队在同一格打完全相同的两场野怪战会撞指纹（视为同一场——方案照常适用，属可接受碰撞）。
- 怪物数量增长（月度 growth）会改变指纹分量 → 下月同格野怪是新指纹（正确行为：敌情变了）。
- 被撞战斗的 dest 残留判定依赖「dest 与英雄相邻」；极端情况（点击攻击相邻格后立即被另一方向的怪拦截）会取到被拦截前一刻的 dest，指纹可能与主动攻击该格混淆——两者若敌情相同则方案通用，无害。
