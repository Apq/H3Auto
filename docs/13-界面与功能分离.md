# 专题：界面与功能分离（重构设计）

> 状态：**批次 1-3 已实施**（2026-10-15）。参考 H3BattleStore `docs/09-界面与功能分离.md` 的分层与分批法。
> 本轮为**纯重构**：不增加也不减少功能；默认构建的钩子挂载点、铠甲语义、像素、时序、日志口径全部不变。
> 分离目的：以后可以整套替换设置面板界面（换皮肤、无界面变体），功能层不动。
> 批次 3（无界面编译变体）仅编译期存在，**不进玩家分发包**、默认构建不定义该宏。

## 1. 目标与非目标

### 1.1 目标

- 功能层（AutoExecute / BattleState / ConfigLog / AttackMagic / ForceField / Entry 钩子外壳）不再引用任何界面实现符号，只经一个显式契约 `IH3AutoUi`（`modules/AutoUiPort.hpp`）。
- 界面（绘制、手势、悬停、命中吞并、拾取屏障、面板草稿编辑）整体成为契约的一个实现，可整体替换。
- 每一批次独立编译、回归、回退；不做一次性大爆炸重写（H3BattleStore 同款纪律）。

### 1.2 非目标（本轮）

- 不改任何钩子挂载点、原函数调用次数与异常传播语义（原函数仍在插件 `__try/__except` 之外恰好一次）。
- 不改存档格式、codec、自动化决策逻辑、时序窗口判定本身。
- 不引入新界面（外部工具等），只留扩展点。
- 不改配置键名、默认值和 user.ini 覆盖优先级。

## 2. 现状耦合盘点（2026-10-15 重构前的事实清单）

以重构前代码为准（行号会漂移，以符号名为锚点）：

1. **功能模块直接 extern 界面函数**（3 处，全部断开）：
   - `AutoExecute.inc.cpp`：`extern IsPanelActive/CloseSettingsPanel`——战斗热键钩子边沿门禁（`CombatHotkeyKbHook_`）与 `ResetAutoState()` 的静默关面板；
   - `BattleState.inc.cpp`：同上两个 extern——`BE_RESULT_SHOWN` 边动作「结算出现：静默关闭设置面板」；
   - `ConfigLog.inc.cpp`：`ResetPanelDrafts()` 前置声明——`ClearConfirmedProfiles()` 清 5 套方案时同步清面板草稿。
2. **钩子外壳住在 UI 文件里**：`Hook_BltComplete`（0x600430）与 `Hook_BattleMsgProc`（0x4746B0）的铠甲外壳与内层都定义在 SettingsDlg.inc.cpp，函数体里功能调用（`CheckAutoFightDialogClosed`、`TryAutoExecuteActiveStack`）与面板绘制/输入/吞并（`s_p`、`DrawPanelToBuffer_`、`HandlePanelInput_`、数字键吞并、hover 坐标离屏）混在同一内层函数。
3. **功能住在 UI 文件里**（批次 2 已处理）：
   - `CheckAutoFightDialogClosed`：战斗生命周期事件源（BattleUI 出现/消失兜底、开面板热键消费 S8、右键自动战斗说明框 → 开面板、结果窗意图观察）；
   - `CheckBattleResultLifecycle_` + `s_result_*`/`s_cpresult_*` 静态量 + 三个对话窗虚表常量 + `s_battle_ui_missing_frames` 等；
   - 依赖的共享工具 `FindDialogByVtable_`（SettingsDlg 与 PanelInput 各有一份静态定义）、`GetBattleItemUnderCursor_`、`IsGameMouseInputActive_`；
   - 另有游戏地址垫片宏 `o_WndMgr`/`o_DDSurfaceBackBuffer` 定义在界面层 PanelGfx，而窗口管理器是功能层也要用的（批次 3 暴露）。
4. **文案资源**：`UiTexts`（T()/g_action_labels/g_panel_title）被 LogPack（打包失败理由）与 AutoExecute（`hud.*` 控制权状态提示）使用。判定：**共享文案资源层，不属于界面实现**——换面板界面后原版提示栏反馈与日志打包理由仍然成立（H3BattleStore 把玩家文案目录归服务层同理）。
5. **判定口径**（与 H3BattleStore 一致）：凡是「换一套界面后仍然成立」的就是功能（方案/草稿提交语义、状态机、指纹、存档、热键配置）；凡是「换界面就没了」的就是界面（像素、手势、悬停高亮、下拉、拾取屏障、帮助模态框）。

## 3. 目标分层

```text
钩子层 Entry.inc.cpp（外壳归位）
   │  只做三件事：生命周期/自动化判定委托、原函数恰好一次、把原生输入翻译成契约调用
   ▼
界面契约 AutoUiPort.hpp（IH3AutoUi，纯抽象接口；宿主 UiPortHost.inc.cpp 定义 g_uiPort）
   │  唯一实现：PanelUiPort_（SettingsDlg 尾部适配器，转发既有静态函数）
   │  兜底实现：FallbackUiPort_（空操作；加载期默认 + 未来无界面变体）
   ▼
功能层 AutoExecute / BattleState / ConfigLog / AttackMagic / ForceField（不感知界面）
   ▼
既有底层（PolicyCore / BattleStoreJsonCore / IniUtf8 / LogPack / CrashGuard）
   ▼
界面实现群（PanelGfx / CellControl / SettingsDlg / PanelInput / PanelDraw / MagicChannel* / UiTexts）
```

## 4. 界面契约（modules/AutoUiPort.hpp）

```text
IsPanelActive() const → bool        // 查询：面板是否打开（热键门禁/复位/结算边）
OpenPanel() → bool                  // 请求开面板，返回是否成功（旧 OpenSettingsPanel_+s_p.active 口径）
ClosePanelSilently()                // 静默关面板（ResetAutoState/结算边）
ResetPanelDrafts()                  // 清面板草稿（ClearConfirmedProfiles）
OnFramePanelTick()                  // 帧的面板部分（BltComplete UI 分支原样迁入）
FilterGameMsg(int* msg) → bool      // 消息吞并/坐标离屏（面板活跃分支内调用）
```

约束：仅游戏主线程；不得在 `__except` 过滤器内调用；禁止把绘制原语、控件命中、布局常量放进契约；每加一个方法必须在本文档登记理由与调用方。`OpenPanel` 当前唯一调用方仍是 SettingsDlg 生命周期事件源（批次 2 随其搬出时改走契约远程调用，契约已就位）。

## 5. 批次 1 实施记录（2026-10-15，已完成）

1. 新增 `modules/AutoUiPort.hpp`（契约）与 `modules/UiPortHost.inc.cpp`（`g_uiPort` + 兜底空实现 `FallbackUiPort_`）；H3Auto.cpp 中紧随 IniUtf8 包含（先于首个使用方 ConfigLog）。
2. 断直连：AutoExecute（热键门禁、ResetAutoState）、BattleState（结算边）、ConfigLog（清草稿）全部改走 `g_uiPort->…`；三个文件不再 extern 任何界面符号。
3. 钩子外壳归位：`Hook_BltComplete`/`Hook_BattleMsgProc`（含铠甲与 `__try` 结构）从 SettingsDlg 整体迁至 Entry；面板分支改经 `OnFramePanelTick`/`FilterGameMsg` 契约；消息钩子的「面板活跃 → 判定后直接返回」结构与原实现逐字一致（不落入主动作提交分支）。
4. SettingsDlg 尾部新增 `PanelUiPort_` 适配器（转发 `s_p.active`/`OpenSettingsPanel_`/`CloseSettingsPanel`/`::ResetPanelDrafts`/帧/消息分支原样迁入），静态初始化期把 `g_uiPort` 从兜底接管为真实面板——先于 DllMain 的 ReadConfig，`ClearConfirmedProfiles` 清草稿行为不变。
5. `CheckAutoFightDialogClosed` 去 `static`（Entry 外部链接调用），本体未动。

行为零变化自检：钩子注册表、两处铠甲 `GuardCrashFilter_(GHID_BLT/GHID_MSGPROC)`、帧内调用顺序（CheckAutoFightDialogClosed → 面板帧或 TryAutoExecuteActiveStack(false)）、消息钩子三分支返回值、清草稿时机全部保持；唯一新增是每帧一次虚调用（远小于一次 Blt）。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| SEH 函数内 C++ 对象展开（C2712）随搬移扩散 | 契约方法不要求展开；适配器方法内仅 POD 局部；每步 0 警告重建把关 |
| 虚调用进热路径 | 每帧一次 + 每条消息一次，远小于既有 blt/消息处理成本 |
| 消息钩子分支穿透（面板开时落入主动作提交） | Entry 镜像原「面板活跃 → 判定后直接返回」结构；FilterGameMsg 契约注释硬性声明调用前提 |
| 静态初始化顺序（ConfigLog 早于界面注册） | g_uiPort 先指向兜底空实现，真实适配器静态期接管；任何时序下空调用安全 |
| 契约膨胀成万能接口 | 禁止绘制原语/命中/布局入契约；新增方法须登记本文档 |
