## 8. 设置面板 UI（源：[SettingsDlg.inc.cpp](<../modules/SettingsDlg.inc.cpp>) + `CellControl.inc.cpp`）

<a id="section-8-0"></a>
### 8.0 模态方案：加固伪模态（不改真模态）

**背景**：曾考虑改为原版 `H3Dlg` 真模态窗口，但真模态靠嵌套阻塞消息循环独占输入，与战场拾取（拾取时需战斗界面响应点击）机制冲突——真模态期间战场被冻结，点不动；要拾取只能关窗重开，体验更差。

**结论**：保留当前**伪模态**方案（自绘到 `screenPcx16` + 自建 hook `Hook_BattleMsgProc`），重点加固：

- 拾取期间确保背景战斗界面不响应误点（屏蔽 hover / 点击穿透）。
- 模态遮挡干净（`ForcePanelModalDepth_` 顶模态计数器）。
- 重绘时机正确（拾取进入 / 退出、格子展开 / 收起边界）。

### 8.1 布局：多级导航 + 一行一格宽卡片（511×110）

面板 680×548，两级结构：顶部第一级为标题 + 方案 1-5 + 本场存档下拉/`?`；左侧 **Tab 导航条**（`TAB_X=17`，项 100×24 纵排；可见页由 `kTabOrder` 决定——当前 **部队**（`PAGE_ARMY`）、**召唤**（`PAGE_SUMMON`）与 **保持状态**（`PAGE_STATUS`）三页，`PAGE_PROFILE` 方案页已移除、停止行全局化（[§8.7](<#section-8-7>)）；新页往 `kTabOrder` 加）。Tab 条与内容区由 **2px 金框色线**框住：竖线 x=119（y=72..456），上/下横线 y=72 / 456（x 17..660，右端对齐内容区右缘 660）。「部队」页 = 卡片表（内容区 **531×342**，x=129..660、y=109；金框线已不再绘制，仅存边界常量 `GRID_FRAME_*`；卡片 **511×110**，第二列/第三列 104/329）。切页 `SwitchPanelPage_` 收尾一切编辑态/下拉、不动草稿；打开面板默认部队页。

卡片容量在 511 宽下全保留：循环施法槽 22px×10/行、移动槽 32px×8/行、近战槽 54px×5/行；保活行（y=78）从第二列起（「保活:」@68、方式下拉@104 宽 118、「剩≤」@230、框@264 宽 92，仅按剩余数量方式显示；下拉列表三选一顺序：不保活 / 剩余数量≤ / 损失量>恢复量——「不保活」在列表最上）。超出用滚动条。

**部队准入与方案生效范围（面板所见 = 生效范围）**：`IsConfigurablePanelStack` 以 `numberAtStart > 0`（本场存在过）为准——**阵亡的己方非召唤部队仍列出卡片**（数量显示 `--`），规则可见可改、复活后继续生效；空槽、召唤物/克隆物（走召唤页共享规则）、弹药车不列，投石车需弹道术。每次**打开面板**把草稿快照到本场部队：非本场槽位的 5 套草稿一律回默认（上一场/已移除部队的驻留规则不随「确定」生效、也不写入存档，日志 `[Panel] 草稿快照：清掉 N 条…`）；**接受战斗结果**时草稿随方案一起清空（[§9.1](<04-方案模型与部队身份.md#section-9-1>)-4）。

### 8.2 普通部队卡小列布局

- **图标小列**（x=5，58×64）：部队 DEF 图标 + 金框（贴卡片顶部；位置/数量仍贴卡片下边缘）。
- **第二小列**（x=68，宽 104）：数量（右对齐）、位置（贴格子下边缘左对齐）；行动下拉（中行 y=30）与允许降级复选框（下行 y=54）同用此列（`CC_COMBO_X=CC_COL2_X`）。
- **顶部整行**（y=5）：标签「行动前循环快捷施法:」+ 单行最多 10 个快捷键小槽（已有项可点开重设，末尾「＋」追加；点后弹模态框按 1-9/0 录入）。
- **第三小列**（x≈178，宽≈329）：选择器下拉，或循环近战 5×2 组合槽，或循环移动 8×2 路径点槽；槽宽按文本宽度定，一行能摆几个就是几个。

### 8.3 下拉展开几何

- 各下拉从其所在小列的行下边缘展开，宽度取所在小列宽（循环施法槽用槽宽）。
- `GetExpandListLeftX / GetExpandListTopY / GetExpandListWidth` 统一计算基准，绘制（`DrawExpandedTo`）、命中（`HitExpandVisibleIndex`）共用。

<a id="section-8-4"></a>
### 8.4 战场拾取（循环近战 / 移动路径）

统一由透明 BattleUI item 作为输入屏障：从消息中的游戏逻辑坐标调用 `SquareAtCoordinates`（`0x464380`）转换当前 hex，并对点击执行 `StopProcessing()`，不使用坐标下拉，也不让点击穿透到真实战斗操作。屏障在**每次打开面板时全新创建并 AddItem 到对话框链尾**（恒为最上层）；停用时仅还原 vtable 并 `HideDeactivate`，旧 item 留链待 BattleUI 析构回收。不复用旧 item 重激活——0.3.2026.930 日志实证：停用后重激活的会话鼠标点击全部失效（消息不再到达屏障），全新安装的会话全部正常，键盘钩子（全局）不受影响。

- **循环近战**：点击已有组合或末尾「＋」后隐藏面板；第一击选择站立格并用 `H3CombatManager::ShadeSquare` / `CCellShd` 临时标示，第二击选择与其不同且相邻的攻击目标格。成功后覆盖或追加记录、撤销标示并恢复面板；第二格相同或不相邻时保持拾取；右键取消且不改原记录。
- **循环移动路径**：点「＋」或已有点后进入拾取，只点 1 格写回对应槽（最多 16）；右键取消不改原记录。
- 面板正常打开及拾取期间均保持战场 hover 屏蔽，避免显示待行动部队的移动范围或攻击提示；设置拾取只显示插件自己的单格临时标示。

### 8.6 帮助说明（右上角 `?`）与悬停 tips

- **悬停 tips（方案 A）**：鼠标悬停在提示区时，底部状态栏显示对应说明文字——命中区：左侧 Tab 条（三页共通）、标题带（热键行：三键名读配置 + 右键「自动战斗」打开）、本场存档下拉、方案 1-5 按钮行、停止输入行（含敌方魔力组合）、勾号/取消按钮；**规则金框内按卡片控件细分**：行动下拉、目标选择器（两者的提示跟随当前选中项，每项一条独立文案）、允许降级为防御、保活方式下拉、「剩≤」阈值框、行动前循环快捷施法行（标签+槽位）、循环移动槽、循环近战槽、展开中的下拉列表，未命中控件的空白处不提示。召唤页另有「启用自动召唤」勾选、法术/行动下拉（跟随选中项）、队数/血量阈值框与说明行的 tips（[§8.8](<#section-8-8>)）。tips 只在光标位置变化时调用状态栏（点存档下拉后光标不动 → 结果文字稳定显示到到期；光标静止悬停在同一目标上仅续期不覆盖；移开后 3 秒到期自动清空；帮助模态打开期间面板 tips 停用）。状态栏是单一富文本通道：`SetStatusText_(text, hold_ms)` 统一设置文本与延时，**任何新调用立即覆盖旧文本并重新计时**（结果消息与 tips 同一规则，无优先级）。命中顺序：表格控件 → 面板按钮表 → 标题文字热键说明兜底——按钮表必须先于标题（存档下拉/方案按钮就在标题行，先前标题带全宽矩形劫持了这些按钮的悬停）；热键说明只在标题文字附近触发（居中绘制，按文字宽估算 ≈ 汉字16px/字+边距24，非整条 680×44）。文本支持 `{颜色名}`（金/绿/红/白/普通/灰/黄/蓝/青/高亮）、`{#RRGGBB}`、`{0xRRGGBB}`、`{rgb(R,G,B)}`、`{XX}` 两位十六进制标记，一行内可混色；RGB 取值映射到当前字体调色板最近色（`TextDraw` 参数本质是调色板索引，非真彩）。tips 整体 `{金}`，存档成功 `{绿}`、失败 `{红}`。
- 设置面板右上角绘制 `?` 按钮。
- 点击后弹出与快捷施法录入同风格的**伪模态**说明框（遮暗面板 + 金框；高 440），内容覆盖：打开方式、5 套方案、循环施法/近战/移动、保活、自动停止（含敌方魔力条件）、召唤、本场存档下拉、右键删除、人工接管热键、设置生命周期，共 9 行。
- 点「关闭」或按 `ESC` 关闭说明；说明打开时吞掉底层点击，不关闭设置面板本身。
- 面板整体居中基础上移 40px（`s_p.y` 计算后减 40，负值截 0）。
- 方案按钮 1-5 = 编号切换：先存回当前编号草稿，面板切到新编号的草稿；内存 5 套草稿独立保留，未载入存档的编号是默认空配置，切走再切回不丢。勾号提交全部 5 套，选中编号立即生效。
- `?` 左侧是**本场存档下拉框**（原「读档」「存档」两按钮已合并，[§17.4](<07-战斗指纹与方案存档.md#section-17-4>)）。点勾号生效时把当前编号写入 `H3Auto.user.ini [General] LastProfile`（下次进面板自动选中；无记录默认 1，不兼容旧版 H3Auto.last.ini）。

### 8.7 保活（部队方式下拉 + 全局停止行）

保活按队三选一（默认不保活，无方案级下拉——保活与召唤同一条施法通道，保活优先，见 [§3.1.1](<03-英雄施法与自动停止.md#section-3-1-1>)/[§3.7](<03-英雄施法与自动停止.md#section-3-7>)）。停止行是**全局常显**行（原「方案」页已移除）：位于 Tab 条右侧内容区上缘、卡片表上方，`STOP_ROW_Y=85`（与 Tab 标签上缘对齐）；部队卡底部是每队自己的方式下拉：

```text
停止行（全局常显）：停止: [10] [✓] 敌方魔力≤[6] 时停   ── 整组 1px 金框
卡片底部：          保活: [不保活 ▼]  剩≤ [2]（仅「剩余数量≤」时显示）
```

- 卡片方式下拉（`CEX_PROTECT`）：label「保活:」+ 下拉框三选一（不保活 / 剩余数量≤ / 损失量>恢复量；「不保活」在列表最上，当前项金色、悬停高亮），点项即选中并收起，点别处/ESC 收起；展开时吞掉底层点击、Enter 不提交设置面板。默认「不保活」，该队永不参与保活施法。
- 「剩≤」阈值框仅方式 = 剩余数量≤时**显示且可点**（不保活/损失量方式下隐藏）；点开按数字键录入，点框外/Enter 写回，ESC 放弃。
- 是否召唤不再在此行选择：召唤启用是召唤页「启用自动召唤」勾选框（[§8.8](<#section-8-8>)）。
- 内容区上缘 y=109、卡片表 `GRID_Y/SCROLL_Y=117`；停止行在内容区上方，卡片/滚动条/确定取消按钮随 `PANEL_H`（548）整体排布。
- 触发时法术自动选（亡灵→聚灵、活体→复活），UI 不出现法术选择。
- 与卡片其余设置同一套草稿/确定提交/取消丢弃；卡片方式随槽位规则按稳定身份整体重排，确定时与 5 套方案一起提交（`CommitProfiles`）。
- 行最右侧是自动停止阈值（[§3.1.2](<03-英雄施法与自动停止.md#section-3-1-2>)）：`停止:` + 数字框，默认 4。点击数字框后按数字键录入，再点框外或按 Enter 写回当前方案草稿；ESC 放弃本次录入。0 表示关闭。阈值随方案提交，也随本场存档保存（[§17](<07-战斗指纹与方案存档.md#section-17>)）。
- 「停止:」右侧是「[✓] 敌方魔力≤[框] 时停」组合（方案级 `g_summon[p].stop_enemy_mana` 勾选 + `stop_mana_th` 阈值，**默认勾选**/阈值默认 6）：勾选启用自动停止第二条件（[§3.1.2](<03-英雄施法与自动停止.md#section-3-1-2>)），阈值框仅数字录入（0..32767，随方案存档）。点击勾选区（框+「敌方魔力≤」文字）切换、与页面无关（部队页/召唤页都能勾）；点阈值框进入录入（与「停止」框同款交互：预填/光标/点外提交/ESC 取消）；「时停」为固定尾签。框在文字左侧（`DrawCheckbox_`）。停止框与敌方魔力组合整组以 1px 金框围住（`STOP_GROUP_*`），提示两者是一起生效的一组。

### 8.8 召唤页（`PAGE_SUMMON`，Tab 条第二页）

Tab 条三页：`部队`（`PAGE_ARMY`，卡片表/滚动条/战场拾取只在本页生效）/ `召唤` / `保持状态`。切页提交数字录入并收起所有下拉；召唤页吞掉内容区点击（部队表/滚动条不响应），方案按钮行、本场存档下拉/勾号/取消/? 照常。布局：

```text
[✓] 启用自动召唤     （与全局「停止:」同一行，y=STOP_ROW_Y=85）
启用后：先判保活，无人可救且满足下方条件时才召唤
魔法: [自动 ▼]
条件: ┌──────────────────────────┐
      │           队数 < [ 2]     │
      │ [和 ▼]    血量 ≤ [ 750]   │
      └──────────────────────────┘
行动: [防御 ▼]  [ ] 允许降级为防御
```

- 「启用自动召唤」勾选框（`SUMMON_ENABLE_*`，与「停止:」同一高度）：方案级 `enabled` 的 UI 开关（默认不勾＝只保活、不召唤）。点击勾选区（框+文字）切换当前方案草稿，与「敌方魔力≤」同款 `DrawCheckbox_`。
- 魔法下拉 5 项：自动 / 气元素 / 水元素 / 火元素 / 土元素（`spell_pick` 0..4）。展开收起/选中/ESC 语义与卡片下拉一致。
- 两个条件包在 1px 金框里：队数单独一行；下一行左侧是「和/或」，右侧是血量。两个条件名从「和/或」右侧同一列左对齐。「队数 <」「血量 ≤」数字框点击进入录入（金色光标闪烁，与停止框同款键盘逻辑：数字/退格/左右移、Enter 写回、ESC 放弃、点框内定位光标、点框外写回）；队数 2..21（严格小于才满足，最小即默认 2）、血量 0..2147483647，空=0。「和/或」是两条件组合方式（和=都满足才召唤，默认；或=任一满足即召唤），点选即存草稿。
- 召唤物行动行（普通行，不做成卡片，选项只有一组）：行动下拉 4 项 手动/防御/散开/随机移动（`GetAllowedSummonActions` + `NormalizeSummonRule` 裁剪规则字段）；「允许降级为防御」复选框**仅随机移动时显示**（框在文字左侧），散开的降级链固定（≥2→≥1→防御）不受勾选影响。
- 悬停 tips：启用勾选、魔法下拉跟随选中项（自动/四系各一条）、行动下拉跟随选中项、队数/血量框、条件组合下拉、行动标签、降级勾选、说明行各一条。
- 随方案草稿存储与提交（战斗存档 JSON 的 `summon` 对象 + 召唤共享规则）；勾号/取消/重开面板与其它草稿同生命周期。

### 8.9 保持状态页（`PAGE_STATUS`，Tab 条第三页）

「保持状态」是方案级列表，不挂在部队卡片上：

```text
只列英雄已学会的全体状态魔法。多个都保持，哪个剩余回合先到阈值就补哪个
剩余回合≤ [3] 时补                      （STATUS_TH_* 阈值行，方案级）
[护盾] [石肤] [血怒] [减速（敌方）]     （每行 4 个槽，STATUS_COLS=4）
[+]
```

- 点「+」追加下一项（占第一个空位，点一下后移）。候选只含当前英雄已学会、且法术表标了 `friendlyMass` 或 `expertMassVersion` 的增益；减速只在专家级时出现，列表里标「敌方」。已加入的不重复出现。最多 8 项。
- **右键删除**：右键已有槽位删除该项，后面的项和「+」前移；「+」追加槽右键无效。
- **阈值行**（说明行与槽位区之间，`s_status_th_*` 编辑态，与停止回合同款数字框：点框进入录入、Enter/点外提交、ESC 取消、切页/切方案前提交）：剩余回合 ≤ 该值（1..9，默认 1）即补；同时作用于友方增益（多到期补剩余最少）与敌方减速的「已覆盖」判定。
- 这些法术都是全体魔法，执行时不选目标格。友方增益与敌方减速都按同一口径：目标侧找到任意一队已有该状态，就按这一队的剩余回合判断；剩余 > 阈值即已保持，≤ 阈值或完全没有时才补。无法接受该法术的个别部队不影响判定。目标侧没有任何可接受的存活部队时不施放，避免原版弹出阻止框。
- 随方案草稿提交，写入战斗存档每个方案对象的 `status`（`buffs` 数组 + `slow` + `refreshTurns`；旧的单独 `slow` 勾选已并入列表）。缺 `status` 或旧档解析失败都视为没有这份状态设置，不读旧格式；`refreshTurns` 缺省（旧记录）读默认 1。

## 字体行高与资源约束

- **字体行高适配（2026-10-07）**：`DrawTxt` 与 `CellControl_DrawText` 两个公共入口对正数文字区域取至少实际 `H3Font::height`，扩高时保持上/中/下对齐锚点，不缩小已有宽裕区域。富文本分段复用 `DrawTxt`。`DrawCheckbox_` 直接按行高与框中心绘制，卡片数量/位置的行距也按字体扩高；字体24px时按比例缩小左列头像及边框，给两行文字留空间，16px头像尺寸不变。所有行动/选择器/保活/召唤/状态/帮助下拉的行距与命中统一按实际行高。本场存档和保持状态列表行距、底板和鼠标命中使用统一实际行高，超过面板可容纳行数时由滚轮访问其余记录。框大小与部队卡片主体布局不变；0/负尺寸仍视为禁用，不擅自开启隐藏绘制。
- 10.07 整合版小字体运行时行高为16，旧标签14/元数据11存在兼容风险。原版 `0x4B51F0` 对14/16居中会整行跳过；实际新版 BINK 的回调并无相同门槛，不能把原版静态机制当作当前缺字唯一原因。构建/几何测试不等于实机显示验收；任意超大字体的整体面板重排不在本次范围，仍应使用能容纳于原面板的字体。
- 资源尺寸严格校验：卡片 / 金框尺寸改动后必须用 `tools/gen_*.js` 重生对应 PCX，否则背景加载失败。
